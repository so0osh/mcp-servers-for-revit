# הכנסת מפת גובה אמיתית (Height Map) ל-Revit לפי קואורדינטות רוחב/אורך (Lat/Lon)

> **ויקי / מדריך** — נלווה לכלי ה-MCP `create_toposolid` וכלי `get_project_location`.

## תקציר

ל-Revit **אין יכולת מובנית** שמורידה אוטומטית מודל גבהים אמיתי (DEM) לפי זוג קואורדינטות
רוחב/אורך גיאוגרפי. ה-API של Revit (כולל גרסת 2027) מאפשר רק **לבנות** קרקע ממידע שכבר יש בידיכם —
נקודות, קווי קונטור, או קובץ CAD/נקודות מיובא (`Toposolid.Create`,
`Toposolid.CreateFromTopographySurface`, "יצירה מ-Import Instance").

כדי לקבל נתוני גובה אמיתיים לאתר בפועל יש צורך באחת מארבע שיטות (pipelines), המפורטות למטה.

| # | שיטה | ניתן לאוטומציה? | דורש שירות חיצוני? | מובנה ב-Autodesk? |
|---|------|-------------------|----------------------|---------------------|
| 1 | גישור Civil 3D / InfraWorks | חלקית (עבודה בדסקטופ) | לא (משתמש בנתוני Autodesk) | כן (AEC Collection) |
| 2 | תוספים חיצוניים (Elk/Rhino.Inside, Topo Setter וכו') | כן | כן (Mapbox/SRTM APIs) | לא |
| 3 | הורדת DEM ידנית + המרה | כן (סקריפטבילי) | כן (USGS/OpenTopography/Google) | לא |
| 4 | **Autodesk Forma** | חלקי (סנכרון בענן, מוכתב ע"י ה-UI) | לא (נתוני Geo של Autodesk עצמה) | כן (AEC Collection) |

השתמשו בכלי `get_project_location` (שרת ה-MCP הזה) כדי לקרוא את `SiteLocation`/`ProjectPosition`
של הפרויקט לאחר שהוגדרה מיקום גיאוגרפי באחת השיטות למטה — זה נותן לכם את עוגן ה-lat/lon
ואת המרת הקואורדינטות בין הפנימי (internal) לבין המשותף (shared) הדרושה למיקום גיאומטריה נכון.

---

## שיטה 1 — גישור Civil 3D / InfraWorks

**מה זה:** צינור העבודה ה"רשמי" של תחום התשתיות. Civil 3D יכול לשלוף נתוני גובה אמיתיים
(USGS, SRTM, או מקור נמדד/סריקת נקודות) וליצור **משטח (Surface)** אזרחי תקין. המשטח מיוצא
כקונטורים או כרשת נקודות ומיובא/מקושר ל-Revit.

**שלבים:**
1. ב-Civil 3D, יצרו או ייבאו **Surface** לאתר (מנקודות מדידה, LiDAR, או DEM שהומר ל-TIN).
2. ייצוא קונטורים כ-DWG (פוליליינים עם גובה) — או ייצוא כקובץ נקודות (`.txt`/`.csv` עם עמודות X, Y, Z).
3. ב-Revit, קשרו/ייבאו את קובץ ה-DWG או הנקודות, ואז השתמשו ב-**Toposolid → Create from Import
   Instance** כדי לייצר את ה-Toposolid מהקונטורים/נקודות המיובאים.
4. הגדירו את `SiteLocation` של הפרויקט (Latitude/Longitude/Elevation) כך שיתאים לקואורדינטה
   האמיתית שבה נבנה משטח ה-Civil 3D, כדי שגיאומטריה עתידית תתאים נכון.

**יתרונות:** נאמנות נתונים גבוהה ביותר, תקן תעשייתי לאתרים גדולים/אזרחיים, שומר מקור אמת יחיד
ב-Civil 3D לעבודות עפר/פילוס.
**חסרונות:** דורש רישיון Civil 3D ושלבי דסקטופ ידניים; שרת ה-MCP הזה לא יכול להריץ זאת מקצה לקצה
(ל-Civil 3D אין API ללא ראש שנחשף כאן).

## שיטה 2 — תוספים חיצוניים (Plugins)

**מה זה:** תוספים קהילתיים/מסחריים ששולפים אריחי גובה (elevation tiles) לתיבת lat/lon נתונה
ומכניסים גיאומטריית קרקע מוכנה ישירות לתוך כלי המידול.

**כלים נפוצים:**
- **Elk** (תוסף Grasshopper, באמצעות **Rhino.Inside.Revit**) — שולף אריחי גובה מ-Mapbox/SRTM
  לתיבת lat/lon נתונה, בונה מש/רשת נקודות, ויכול להזרים אותם ל-Revit דרך Rhino.Inside.
- **"Topo Setter" ותוספי Revit דומים** — מייבאים תמונת heightmap (גווני אפור) ומתרגמים ערכי
  אפור לנקודות גובה בסקאלה נבחרת.
- **תוספי ייבוא GIS** — קוראים קבצי DEM גולמיים (`.tif`/`.asc`) והופכים אותם לרשת נקודות
  מוכנה ל-Toposolid בתוך Revit.

**שלבים (כלליים):**
1. התקינו את התוסף (Elk, Rhino.Inside.Revit, או תוסף GIS ל-Revit).
2. הזינו את תיבת ה-lat/lon של האתר (או סמנו מיקום על מפה בתוך הכלי).
3. התוסף קורא לשירות הגובה שברשותו (Mapbox Terrain-RGB, SRTM וכו') ומחזיר רשת נקודות/מש.
4. המירו/ייצאו את הרשת לגיאומטריה שמובנת ל-Revit (נקודות Toposolid או Import Instance).

**יתרונות:** ניתן לאוטומציה מלאה, סקריפטבילי (הגדרות Grasshopper יכולות לרוץ ללא ראש - headless),
מתאים לסטודיות אתר גנרטיביות/פרמטריות.
**חסרונות:** תלוי במפתח API של צד שלישי ובמגבלות שימוש (Mapbox וכו'); רזולוציית הנתונים משתנה
לפי הספק והאזור; לא צינור עבודה נתמך ע"י Autodesk.

## שיטה 3 — הורדת DEM ידנית + המרה (בנייה עצמית)

**מה זה:** הורידו מודל גבהים דיגיטלי (DEM) לאתר בעצמכם והמירו אותו לפורמט שכלי
`create_toposolid` מצפה לו (גבול + נקודות פנימיות, או רשת נקודות).

**מקורות נתונים:**
- **USGS 3DEP** (ארה"ב, רזולוציה ~1מ'–30מ', חינמי)
- **OpenTopography** (עולמי, DEM-ים חינמיים שונים: SRTM 30מ', ALOS וכו')
- **Google Maps Elevation API** (דגימת נקודות, בתשלום מעבר לרמה החינמית)
- **Copernicus/ESA DEM** (עולמי, חינמי, רזולוציה גסה יותר)

**שלבים:**
1. קבעו את תיבת התיחום של האתר מתוך `get_project_location` (או תיבת lat/lon שמוגדרת ידנית).
2. הורידו את קובץ ה-DEM (GeoTIFF) שמכיל את התיבה הזו מאחד המקורות למעלה.
3. דגמו את הרסטר במרווח רשת נבחר (למשל כל 5 מ') כדי לקבל מערך של שלשות
   `(lat, lon, elevation)`.
4. המירו כל זוג `(lat, lon)` לקואורדינטת XYZ פנימית של Revit באמצעות ה**היפוך** של הטרנספורם
   הגיאודטי + `ProjectPosition` המתואר בתיעוד `get_project_location`:
   - הטילו את ה-lat/lon למרחק מטרי מקומי (הטלה שווה-מלבנית/UTM ממורכזת בנקודת המדידה - Survey Point).
   - סובבו לפי `-ProjectPosition.Angle` והוסיפו את ה-`EastWest`/`NorthSouth`/`Elevation` של
     הפרויקט כדי לנחות בקואורדינטות פנימיות (רגל).
5. הזינו את רשת הנקודות שהתקבלה לתוך `create_toposolid` (כגבול + נקודות פנימיות אופציונליות)
   כדי לייצר את הקרקע.

**יתרונות:** אין תלות בתוסף או בשירות ענן של Autodesk; ניתן לסקריפט/הרצה ללא ראש (headless) במלואה
— זו הגישה ששרת ה-MCP הזה עצמו יכול להפוך לאוטומטית מקצה לקצה (סקריפט בצד השרת/הסוכן + כלי
ה-`create_toposolid`/`get_project_location` של MCP זה).
**חסרונות:** אתם אחראים על מתמטיקת ההטלה ועל איזון איכות-הנתונים; מקורות DEM חינמיים יכולים להיות
גסים (רזולוציית 30מ') לאתרים קטנים/עירוניים.

> **זו השיטה שמתאימה הכי טוב ל"שרת ה-MCP עושה הכל".** במידת הצורך, ניתן לבנות כלי נוסף
> (`create_toposolid_from_heightmap` או דומה) שמקבל רשת lat/lon + מערך גבהים ומבצע את המרת
> הקואורדינטות + קריאה ל-`create_toposolid` באופן פנימי.

## שיטה 4 — Autodesk Forma

**מה זה:** Forma (לשעבר Spacemaker) הוא מוצר ניתוח אתרים מבוסס-ענן של Autodesk. הצבת נעץ במיקום
אמיתי (כתובת/lat-lon) בתוך Forma גורמת לו **לשלוף אוטומטית** גובה קרקע, בניינים סובבים, כבישים
ושכבות GIS נוספות לאותו אזור ממסדי המידע הגיאוגרפיים שלו עצמו — ללא צורך במקור DEM ידני.

**שלבים:**
1. פתחו את Forma (אפליקציית web), חפשו/הצבו נעץ במיקום האמיתי של האתר.
2. Forma ממלאת אוטומטית קרקע + הקשר (בניינים, כבישים) לאזור הזה.
3. ב-Revit (2024–2027), פתחו את **תוסף Forma** (בסרגל Add-Ins) והתחברו לאותו פרויקט Forma.
4. השתמשו ב-**Import from Forma** כדי להכניס את הקרקע ל-Revit — היא מגיעה כ-`Toposolid`
   (Revit 2024+) / `TopographySurface` (גרסאות ישנות יותר), כאשר המיקום הגיאוגרפי
   (`SiteLocation`) כבר מוגדר אוטומטית.
5. אופציונלי: העלו מסה (massing) מ-Revit חזרה ל-Forma לצורך ניתוח שמש/רוח/רעש/צפיפות.

**יתרונות:** צינור עבודה מובנה של Autodesk במלואו, אפס טיפול ידני בנתונים, מיקום גיאוגרפי
מוגדר אוטומטית, דו-כיווני (Revit ↔ Forma).
**חסרונות:** דורש מנוי **AEC Collection** עם הרשאת Forma; הסנכרון מוכתב ע"י ה-UI בענן של
Autodesk — **אין שטח API ציבורי/סקריפטבילי לפעולה זו מתוך `RevitAPI.dll`**, ולכן לא ניתן
להפוך אותה לאוטומטית משרת ה-MCP הזה. זהו שלב ידני, חד-פעמי (או מתעדכן לעת הצורך) שבן-אדם
מבצע ב-UI של Revit לפני שכלי ה-MCP שלכם נכנסים לפעולה למידול פרוגרמטי.

## טבלת המלצות

| צורך | השיטה המומלצת |
|------|------------------|
| אתר אזרחי/גדול, צינור עבודה קיים עם Civil 3D | **1 — Civil 3D/InfraWorks** |
| מחקר מסה גנרטיבי/פרמטרי מהיר, סקריפטבילי דרך Grasshopper | **2 — תוסף חיצוני (Elk)** |
| צינור עבודה ללא-ראש (headless) מלא ששרת ה-MCP יכול להריץ מקצה לקצה | **3 — DEM ידני + `create_toposolid`** |
| פרויקט אמיתי חד-פעמי, איכות Autodesk מובנית ללא טיפול נתונים | **4 — Forma** |

## כלי MCP רלוונטיים

- `get_project_location` — קריאת `SiteLocation`/`ProjectPosition` (lat/lon, גובה, והמרת
  הקואורדינטות בין פנימי למשותף) לאחר שהוגדר מיקום גיאוגרפי באחת השיטות למעלה.
- `create_toposolid` — בניית אלמנט ה-Toposolid מלולאות גבול + נקודות (Revit 2027 ואילך).
